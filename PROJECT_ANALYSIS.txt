PRICING LOGIC
-------------
Regular Car Rental (RentController.SubmitRequest):
  FinalPrice = Car.Price
             x FestivalMultiplier (from FestivalService, based on RentalDate)
             - 10% if user.RegularCustomer == true

Offer Rental (HomeController.SubmitRequest):
  FinalPrice = Offer.Price - (DiscountPercentage% of Offer.Price)
  NOTE: Festival multiplier is NOT applied to offer rentals.

Khalti payments:
  - Multiply by 100 before sending (Khalti uses paisa units)
  - Divide by 100 on callback

FULL USER BOOKING FLOW
-----------------------
1. Customer visits Home page -> sees car listing
2. Clicks "Book" -> HomeController.BeforeKhalti()
   a. If IsCarBooked=true  -> redirect (car unavailable)
   b. If CanBook=false     -> error "Pay damage charge first"
   c. If IsProfileComplete=false -> go to Rent/Index (complete profile)
3. Profile completion -> RentController.Index -> UpdateUser (POST)
4. Redirect to RentController.RentDescription (car + user info shown)
5. Customer picks payment method:
   a. Cash   -> RentController.SubmitRequest -> Rent saved (Verified=false)
   b. Khalti -> RentController.KhaltiPayment -> redirect to Khalti
             -> SuccessPayment callback -> Rent saved (Verified=false)
6. Car marked IsCarBooked=true, BookedCount incremented
7. Staff/Admin sees request in RentsController.Index
8. Staff approves -> RentsController.Edit
   -> Verified=true, RentalHistory created (Status=true), email sent
9. Customer returns car -> RentsController.Return -> IsCarBooked=false

[CRITICAL] FestivalService.DeleteFestivalAsync - Logic Inverted
---------------------------------------------------------------
File: Services/FestivalService.cs, Line 57

CURRENT CODE (BROKEN):
  var festival = await _context.Festivals.FindAsync(id);
  if (festival != null)   // <-- WRONG: should be == null
      return false;
  _context.Festivals.Remove(festival);  // NEVER reached

EFFECT: Festivals can NEVER be deleted. The null check is backwards.

FIX:
  if (festival == null)
      return false;
  _context.Festivals.Remove(festival);
  await _context.SaveChangesAsync();
  return true;

[CRITICAL] RentController.SuccessPayment - Crash on Khalti Callback
---------------------------------------------------------------------
File: Controllers/RentController.cs, Line 457

CURRENT CODE (BROKEN):
  string rentalStartString = HttpContext.Request.Query["rentalStart"];
  string urlWithoutQueryParams = rentalStartString.Substring(
      0, rentalStartString.IndexOf('?'));  // crashes if no '?' found

EFFECT: If '?' is not in rentalStart string, IndexOf returns -1,
        causing ArgumentOutOfRangeException crash.

FIX:
  int idx = rentalStartString.IndexOf('?');
  string cleanDate = idx >= 0
      ? rentalStartString.Substring(0, idx)
      : rentalStartString;
  DateTime rentalStart = DateTime.Parse(cleanDate);

========================================================
  STAFF ROLE INVESTIGATION — DETAILED FINDINGS
========================================================

VERDICT: There is NO "Staff" role in this project.
         Only two roles exist and are used: "Admin" and "Customer".

EVIDENCE FROM THE CODE:
-----------------------

1. _Layout.cshtml (the main navigation/sidebar file):
   - Only two role checks exist in the ENTIRE navigation:
       @if (User.IsInRole("Admin"))    -> shows Admin sidebar
       else if (User.IsInRole("Customer")) -> shows Customer sidebar
   - There is NO sidebar or navigation for a "Staff" role.
   - A user who is not Admin or Customer sees only the public
     navbar (Home, CarList, About, Contact).

2. All Controllers — role checks found:
   - User.IsInRole("Customer")  -> used in 5 controllers
   - [Authorize(Roles = "Admin")] -> used in FestivalController
   - User.IsInRole("Admin") -> used in Views (Rents, DamageRequest, Offer)
   - "Staff" -> NEVER used in any IsInRole() or Authorize(Roles) check

3. StaffRegistrationController.cs:
   - This file IS referenced in build_output.txt (it was compiled
     at some point in the past), but the file NO LONGER EXISTS
     in the Controllers folder.
   - It was likely DELETED by the developer at some point.
   - The build_output.txt is a leftover artifact from an old build.
   - What it did: It had fields like Roles, FirstName, LastName,
     Email, Address, Password, ConfirmPassword — it was a form
     to register staff accounts. But it's gone now.

4. Mentions of "Staff" word in comments only:
   - RentController.cs line 223: "public bool IsStaff { get; set; }"
     -> This field is in UserAndCar viewmodel but always set to false.
     -> It is never used for role-based access control.
   - HomeController.cs line 42: "public int StaffCount { get; set; }"
     -> This field is in CarViewModel but always set to 0 (hardcoded).
   - Comments like "// Processes refund done by the staff" are just
     informal comments — not enforced role checks.

WHAT THIS MEANS:
----------------
- In the current live codebase, there are only 2 effective roles:
    ADMIN    -> Full access to everything (all CRUD, reports,
                festivals, approvals, damage management)
    CUSTOMER -> Can browse cars, submit rent requests, view own
                history, report damage, view refunds

- The concept of a "Staff" role was PLANNED (StaffRegistrationController
  existed) but was ABANDONED. The developer removed the file but
  left behind: the IsStaff field (unused), StaffCount field (always 0),
  and some informal comments using the word "staff".

IMPACT ON THE SYSTEM:
---------------------
- Any user who is assigned a role other than "Admin" or "Customer"
  (e.g. someone manually given a "Staff" role in the database)
  will see ONLY the public navbar — no dashboard, no management panel.
  They would be effectively locked out of all features.

- The navigation has no "else if (IsInRole("Staff"))" branch.

RECOMMENDATION:
---------------
Either:
  A) Remove all traces of "Staff" (clean up IsStaff field, StaffCount,
     and informal comments) to make the code accurate.
  OR
  B) Re-implement the Staff role properly with its own sidebar,
     restricted CRUD access, and a staff registration flow.
